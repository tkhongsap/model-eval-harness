==============================================================================
3. WHY THE ARM IS NOT SCORED ON 120 CALLS
==============================================================================
120/138 is 87.0%, below the coverage gate of 90% of the truth set.
The gate is deliberately written against the TRUTH SET rather than against the run's own
rows, because a run that lost items would otherwise shrink its own denominator and report a
healthy-looking score over whatever survived. That is not hypothetical here: a VPN drop once
left an arm scoring 0.358 over 130 of 414 calls.

So the arm is reported UNAVAILABLE, which is one of the plan's preregistered permitted
verdicts, and no partial number is published.

==============================================================================
4. WHAT THIS IS NOT EVIDENCE OF
==============================================================================
It is NOT evidence that Qwen3-ASR is unreliable in production. One gateway, one afternoon,
under a load pattern this evaluation created by running two ASR models concurrently against
it. Typhoon completed 135 of 138 on the same gateway in the same window
and its 3 losses were the same transport error, all three succeeding on a quiet retry.

What it IS evidence of, and this is separate and already recorded: on the E23 corpus
Qwen3-ASR produced 16 catastrophic runaway repetitions in 138 calls (11.6%) against
Typhoon's zero, and normalised CER 0.1127 against 0.0452. The reliability argument for
Typhoon rests on THAT, measured over a completed run, and not on this outage.

TWO THINGS FOLLOW.

First, this is not about Qwen3-ASR specifically. Section 4 already said the outage is not
evidence about that model, and the labeller going down the same way settles it: whatever is
wrong is upstream of both.

Second, and this is the luckier one: the E24 label run had ALREADY COMPLETED when this
happened. All 1,656 records across four arms were written between 07:40Z and 09:38Z. Had
the backend gone down ninety minutes earlier, the run would have died mid-flight and the
coverage refusal would have voided three arms rather than one.

Nothing in this file is a reason to re-run anything that completed. The four arms that
finished are scored against a frozen corpus, with model identity recorded per call, and
they do not become less true because the gateway fell over afterwards.
