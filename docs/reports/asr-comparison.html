Transcribing Thai calls: production Gemini against our own GPU

Production sends audio to Gemini and gets labels back in one call. A text-only model cannot do that — it needs a speech-to-text step that does not exist in our stack today, and every label downstream inherits its errors. This measures that step.

Synthetic audio · no customer data · no production calls

20 Thai call-centre recordings, 3.6–9.5 minutes each, 123.6 minutes in total. Ten mechanism families, two calls each, paired so the two calls in a family take different scenarios and opposite speaker genders — a family effect can therefore never be a voice effect.

The reference is exact by construction. The dialogue was authored first and the audio synthesised from it, so the transcript is not an estimate of what was said — it is what was said. Reference error is removed entirely as a term in every figure here. Both arms ran on 2026-08-17.

2. Read this before the numbers

Both models work. Both also fail, in different ways, and neither failure is visible without a reference to check against. That is the finding this set exists to produce, and it matters more than the ranking below it.

Gemini 2.5 Flash — Silently dropped passages
On ASR-006, ASR-019 whole passages of dialogue are simply absent — up to 1,280 characters deleted with almost no insertions, which is the signature of dropped content rather than mishearing. The transcripts begin and end coherently; the middle is missing. Nothing in the response indicates it happened.
Qwen3-ASR 1.7B — Degenerate repetition on one file
On ASR-012 it produced 58,546 characters against a 3,405-character reference — a single ~100-character span repeated 496 times. Re-running that file gave a byte-identical result, so it is deterministic, not a sampling fluke. It is also visible without any reference: that call ran at real-time factor 1.05 against ~0.065 on every other file. This one item is 83% of the arm’s total character error; excluding it the pooled rate is 0.120 rather than 0.673.

Neither failure announces itself. Both arms returned HTTP 200 on all 20 calls and wrote a well-formed transcript every time. An eyeball check of the opening lines would pass both.

3. Accuracy

Character error rate is the headline, with one caveat that changes it completely. A pooled corpus rate is the right way to aggregate ASR — averaging per-file rates would weight a 3-minute call the same as a 10-minute one — but it also means a single degenerate transcript can dominate. Here one does: Qwen3-ASR’s ASR-012 contributes 83% of its total character error, and pulls its pooled rate from 0.120 to 0.673. The chart shows the pooled figure as measured; the per-call table in section 7 shows what it is made of.

Thai is written without word spaces, so a character distance is the only figure that does not depend on a tokeniser's opinion. Both arms are scored by the same code (bed27990c125…) against the same references (9ab5bcbb4e13…), pooled over the corpus rather than averaged over per-file rates.

5. The two figures that need a caveat before you read them

6. What this comparison cannot control

The two arms write numbers differently, and the reference only matches one of them. The ground truth spells numbers out as they are spoken (“สิบแปด สิงหาคม”). Gemini does the same — because the prompt written for it in this project asks it to. Qwen3-ASR writes digits (“18 สิงหาคม”), which is a rendering choice, not a mishearing: the number was heard correctly. Character error rate charges it anyway, for every date, amount, phone number and case id in the corpus. Measured outside the scorer on the nineteen non-degenerate items, reading those digit runs back as spoken Thai moves CER from 0.153 to 0.087 — so roughly two fifths of the internal model’s character error is number formatting. That figure is an estimate, not a published metric: forgiving a rendering difference is a change to the scoring contract, and that contract is a closed list amended by review rather than mid-run.

Entity recovery once appeared to point the other way. It was a measurement fault, and it has been fixed. Until 2026-08-17 this page would have reported 92.9% against 67.5% in the internal model’s favour. That gap was not real: the surface test was an exact substring match that included spaces, so an arm writing the same words with different phrase spacing scored the entity as lost. Of the production model’s 151 apparent misses, 136 — 90% — were present in its own transcript and spaced differently. With the test made whitespace-insensitive on both sides, the two arms land on exactly the same figure. Entity recovery is what maps to money, since production writes these values into fields, so it is worth being precise that on this set it does not separate the arms at all.

The two arms are not given the same help. Gemini is a general model steered by a prompt, and its prompt asks for Thai-script brand names. Qwen3-ASR is a dedicated transcription endpoint: its prompt parameter is accepted and ignored — measured, byte-identical output with and without. So Gemini has an advantage on brand names that the other arm cannot be given. Inherent to the comparison, not a choice made here.

Word spacing is a style difference, not an accuracy difference. One arm emits spaces between words and the other does not. Thai has no native word spaces, so neither is wrong — but the tokeniser charges one of them for it. This is why CER leads and WER is reported beside a warning.

Speed is not like-for-like and is deliberately not charted. Gemini was called over the public internet; the internal model over the datacentre network. Those numbers measure two deployments, not two models.

The audio is synthetic. It was generated from authored text by a neural TTS voice, and carries only the acoustic damage the degradation chain explicitly models. Two voices cover all 20 calls, so speaker variability is not tested at all. A CER measured here is not a production CER estimate.
