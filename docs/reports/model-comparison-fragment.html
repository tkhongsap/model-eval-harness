How the verdict is decided

On most calls both models give the same answer, and those tell you nothing about which is better. Only the calls where one was right and the other wrong carry information. The question is then simply: is that scoreboard lopsided enough that chance cannot explain it?

Worked example — Qwen3.8 on reason

Of 138 calls, both models got 64 right and both got 46 wrong. Those 110 are ties and are set aside. That leaves 28 calls where they differed: Qwen3.8 won 10, Gemini won 18.

The margin required depends on how many disagreements there are. At 28 differences the gap has to reach 14 for chance to be ruled out; this one is 8, so the row reads “no real difference”.

Every comparison below is Gemini against one challenger, on the same 138 calls. The four counts on each row are what happened on those calls, and they always add up to 138. Only the last two columns decide the verdict — the first two are ties.

Two things this makes visible that an average cannot. First, why so many verdicts are “too few to call”: on product the models agree on almost every call, so there is barely anything left to measure — that is not a pass and not a fail, it means this test set cannot separate them. Second, why Reason scores lower for everyone: on that dimension 42–48 of the 138 calls were failed by both models. It is hard for everything we tested, not a weakness of one model.

4. Consistency

Each transcript was sent three times, byte-identically. A stable model returns the same labels every time.

Qwen3.8 27B changed a scored label 6 times across 414 calls; production Gemini changed one 29 times. All four rewrite their prose between repeats — what differs is whether the change reaches a label anyone acts on. Gemini rewrote its text on 111 of 138 calls here; it was bit-stable when measured on 10 August, with no change on our side.

What the three label types are

Each model reads a Thai call-centre transcript and fills in three fields, scored separately because they fail in different ways.

Call outcome

4 possible values

How the call ended: save (customer stayed), churn (left), unknown, undefined. Drives retention reporting.

Reason

11 possible values, up to 3 per call

Why the customer wanted to cancel: save cost, network, contract end, post to pre and others. The hardest of the three — every model scores lowest here.

Product

4 possible values, all must be right

Which products the call was about: postpaid, tol (home broadband), tvs (TrueVisions), unknown. Scored as an exact set.

What the evaluation set is

138 Thai call-centre transcripts written in-house for testing, with hand-checked correct answers. No customer data, no production transcripts, nothing confidential. Each model made 414 calls (138 transcripts × 3 repeats).

Because the set is synthetic, every accuracy figure here — Gemini’s included — is an upper bound. Real calls are messier. This ranks the models against each other; it does not predict production accuracy.

Bottom line

Qwen3.8 27B on our own GPU is the strongest internal candidate. It is not measurably behind production Gemini on any of the three label types. On call outcome and product the two models disagreed on too few calls to call a winner either way.

Gemma 4 12B is out. Measurably worse than Gemini on all three.

What still blocks a migration decision: the speed gap (real, though confounded by concurrency and network path — see section 3), and the fact that this is a synthetic test set. Before any production call we would need the same comparison against real labelled calls.
