## 5. Steps & Reasoning
Follow these steps sequentially to analyze the call transcript:

1. **Identify speaker roles** - Determine who is Agent and who is Customer based on conversation content and behavioral patterns (not just position)
2. **Read the entire transcript** from opening to closing to understand the complete conversation flow
3. **Determine call completion status** - Focus on WHEN customer ended the call in conversation flow. Output "Completed" if call reached end stage (offer accepted/rejected, main business done, near closing - even if customer ended quickly without perfect closing). Output "Abandoned" ONLY if customer hung up EARLY before conversation reached its purpose (e.g., during opening/consent, customer says "ไม่สะดวก"/"ไม่สนใจ" and ends immediately, or sudden disconnection during offer presentation) OR technical issues caused immediate disconnection before call could reach natural end.
   - **Abandon call types** — both result in `call_status = "Abandoned"` and ALL 1.2 verification fields = `null`:
     - **Customer drops:** Customer hangs up mid-call before transaction completes
     - **System/technical drop:** Call disconnects due to technical issues
   - **NOT abandon — agent redirects to registrant:** If agent deliberately drops the call to contact the registrant outbound (without customer rejection or technical issue) → `call_status = "Completed"`. ALL 1.2 verification fields are still `null` (agent redirected before verification, not a compliance violation).
4. **Identify the call opening section** - evaluate agent identification (must provide greeting and agent name), call origin disclosure, and consent request
5. **Determine sale/service completion status** - CRITICAL: Did customer accept offer and complete transaction? This determines whether verification fields are None vs True/False
6. **Assess language and tone throughout** - detect inappropriate language, clarity issues, or pacing problems
7. **Analyze active listening behaviors** - identify probing questions and needs assessment depth
8. **Evaluate the call closing** - check for resolution confirmation (if sale completed, must confirm; if no sale, optional), courtesy, and smooth ending allowing customer opportunity to respond
9. **Evaluate sales effectiveness** - assess needs analysis, offer presentation, objection handling, and closing attempts
10. **Evaluate customer experience** - assess empathy, communication clarity, and trust building
11. **Verify compliance** - check data privacy (data scope, company disclosure, no pressure — NOT consent before presenting), sales transparency, and professional conduct
12. **Apply campaign-specific evaluation** - follow additional evaluation steps defined in the campaign checklist (if applicable)
13. **Analyze campaign ratio** - determine what percentage of conversation discusses main campaign vs other topics (must sum to 1.0)
14. **Map observations to boolean criteria** - for each sub-criterion, determine True (compliant) or False (non-compliant). **CRITICAL NULL RULE:** When no sale completed OR no opportunity exists, you MUST output the JSON keyword `null` (the 4 letters: n-u-l-l), NOT the word false
15. **Generate support_detail for each sub-category** - Write concise (max 100 tokens) explanation with evidence quotes, explaining why evaluations were made
16. **Summarize agent_strength** - Identify 2-4 key strengths across all categories with specific examples (max 800 chars)
17. **Summarize agent_weakness** - Identify 2-4 key weaknesses/improvement areas across all categories with specific examples (max 800 chars)
18. **Structure the output** according to the JSON schema

## 6. Rules & Constraints
- Evaluate based on **actual conversation content**, not assumptions
- Boolean outputs must be **True** (criterion met/compliant) or **False** (criterion not met/non-compliant)
- **CRITICAL - NULL OUTPUT REQUIREMENT:**
  - **Python None = JSON null** - When you determine a value should be None/null, you MUST output the JSON keyword `null`
  - **Customer Identity Verification:** If NO sale/service completed → output `null` for all three fields
    - CORRECT: `"customer_verification": null, "invalid_verification": null, "missing_verification": null`
    - WRONG: `"customer_verification": false, "invalid_verification": false, "missing_verification": false`
    - **Abandon calls (customer/system drops):** Also output `null` for all three 1.2 fields — treated same as no sale completed
    - **Agent drops to call registrant without asking (not abandon):** Also `null` for all three fields — deliberate redirect, not a violation
  - **Cross-sell/Upsell:** If NO opportunity exists → output `null` for all three fields
    - CORRECT: `"missed_crosssell_upsell": null, "unclear_addon_separation_crosssell": null, "inadequate_addon_disclosure_crosssell": null`
    - WRONG: Using `false` when there's no opportunity
  - **Remember:** `false` means "attempted but failed", `null` means "not applicable/no opportunity"
- **Thai language keywords** are provided as detection signals - use them to identify behaviors
- Consider both **positive indicators** (presence of good behaviors) and **negative indicators** (presence of violations)
- If a criterion cannot be evaluated due to insufficient information, default to **False**
- Focus on **agent behavior only** - customer behavior is context, not evaluation target
- Each sub-criterion is **independent** - evaluate separately
- Do not conflate multiple criteria - assess each boolean field precisely
- **Outbound context:** Agent initiates contact, so call opening requirements are stricter
- **CRITICAL - Proper Identification Requirements:**
  - **proper_identification = True** ONLY when agent provides greeting AND agent name
  - **Missing required components = False** - Common errors:
    - Agent says greeting but NOT name → False
    - Agent starts selling without proper introduction → False
    - Missing greeting or name → False
  - **Verify keywords:** สวัสดีครับ, สวัสดีค่ะ, ดิฉันชื่อ, ผมชื่อ
- **Campaign-specific rules:** Follow additional evaluation rules and constraints defined in the campaign checklist (if applicable)
- **Speaker identification:** Must be based on conversation content and behavior patterns, not position order (customer may speak first in outbound calls)
- **Support detail requirements:**
  - Each sub-category group requires a `support_detail` field (string, max 400 characters, ~100 tokens max)
  - **LANGUAGE:** Must be written in Thai language
  - **PURPOSE:** Provide EVIDENCE and EXPLANATION, NOT field values
  - **WRONG:** "customer_verification: False - พนักงานไม่ได้ยืนยัน. invalid_verification: False."
  - **CORRECT:** "พนักงานไม่ได้ถามยืนยันตัวตนเลย ดำเนินการให้ลูกค้าทันที" (cite conversation evidence in Thai)
  - Must quote actual conversation in Thai showing evidence
  - Explain WHY evaluations were made based on what happened in the call
  - Be concise but specific - cite key phrases, not full sentences
  - For None values: explain why in Thai (e.g., "ไม่จำเป็นต้องยืนยันตัวตน เนื่องจากไม่มีการขายสำเร็จ")
  - Address all fields in the group briefly
- **Agent Strength & Weakness Summary requirements:**
  - `agent_strength`: Summarize 2-4 key strengths demonstrated across all evaluation categories (max 800 chars)
  - `agent_weakness`: Summarize 2-4 key weaknesses/improvement areas across all categories (max 800 chars)
  - Reference specific behaviors from the call with brief examples
  - Focus on patterns, not isolated incidents
  - Balance across categories (operations, sales, CX, compliance)
  - Write in Thai language for authenticity

**support_detail Guidelines:**
- **Language:** Write in Thai language
- **Length:** Maximum 400 characters (~100 tokens maximum)
- **Content:** Quote exact agent/customer phrases (in Thai, with quotation marks) that justify each True/False/None decision
- **Scale with False count:** More False evaluations = more detailed explanation required. Each False MUST include the exact quote (or note of silence) + what criteria was not met
- **Format Example:** "พนักงานแนะนำตัวครบ 'สวัสดีครับ ผมชื่อสมชาย รหัส...' ถามความสะดวก 'สะดวกคุยสายไหมครับ' รอคำตอบก่อนดำเนินการต่อ"
- **For null values:** Explain WHY in Thai using natural business language - quote the conversation moment proving no opportunity existed
  - **DO NOT write field names or values** like "customer_verification=None" - business users don't need technical details
  - Good: "ลูกค้าปฏิเสธข้อเสนอทั้งหมด 'ไม่สนใจครับ' และตัดสายไป ไม่มีการทำรายการซื้อขาย จึงไม่จำเป็นต้องมีการยืนยันตัวตน"
  - Good: "ไม่มีโอกาสในการเสนอขายเสริม เนื่องจากลูกค้าบอกว่ากำลังขับรถและไม่สะดวกคุยสาย"
  - Bad: "customer_verification=None, invalid_verification=None" (don't write field names!)
  - Bad: "ไม่มีการยืนยันตัวตน" (too vague - doesn't explain why or quote evidence)
- **For False values:** State what was expected, quote what actually happened (or note silence), explain the gap
  - Good: "พนักงานไม่ได้ถามความสะดวก เริ่มนำเสนอโปรโมชั่นทันทีหลังแนะนำตัว 'มีโปรดีๆ มาแนะนำค่ะ' ไม่มีการขออนุญาตลูกค้าก่อนดำเนินการ"
  - Bad: "พนักงานไม่ได้ถามความสะดวก" (no evidence of what happened instead)
- **Be concise:** Key phrases only, not full sentences

**agent_strength & agent_weakness Guidelines:**
- **Length:** Maximum 800 characters each
- **Content:** Summarize overall performance patterns across all categories
- **Structure:** List 2-4 key points with specific behavioral examples
- **Language:** Write in Thai for authenticity
- **Coverage:** Balance across operations, sales, customer experience, and compliance
- **Examples:** Include brief quotes or specific behaviors demonstrating each point
- **Focus:** Strengths = what agent did well consistently; Weaknesses = improvement opportunities with impact
